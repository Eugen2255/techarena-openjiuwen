# Инструкции для ИИ-ассистентов (Codex, Claude Code и др.)

Это репозиторий харнесса для соревнования TechArena 2026 (НГУ). Харнесс на базе openJiuwen решает
100 задач за фиксированный бюджет токенов и должен набрать максимум баллов.
Подробности: `docs/regulations.md` (правила), `docs/organizers_faq.md` (ответы организаторов — главнее
регламента там, где они расходятся), `docs/pipeline.md` (план), `START_HERE.md` (как начать).

## Жёсткие ограничения (нарушение = незачёт)

- Запуск у организаторов: `python /app/run_agent.py --tasks-dir /data/tasks` в Docker с флагами
  `--read-only --tmpfs /tmp --cap-drop ALL`, без сети (кроме LLM-прокси), 1 час, до 5 сессий агента.
  Писать можно **только** в `/tmp` и в `/data/tasks`.
- При запуске ничего не скачивать: всё нужное ставится в образ при сборке (`Dockerfile`).
- Образ < 4 ГБ, сборка < 1000 с, все версии зафиксированы (`requirements.txt` с `==`, базовый образ по digest).
  openJiuwen — **последней версии** с официального сайта (сейчас `0.1.20.post1`).
- LLM — только через `LLM_BASE_URL`/`LLM_API_KEY` и только 4 модели из `harness/config.py:MODELS`.
  На прогоне `LLM_BASE_URL=https://api.neuraldeep.ru/v1` — тот же NeuralDeep, что при разработке, с лимитами
  60 запросов в минуту и **3 одновременных запроса на аккаунт**. Токены рассуждений входят в `completion_tokens`.
  Локальные нейросети запрещены (классические регрессия и бустинг можно).
- Бюджет токенов (out + in/10) — ровно 100K; `BUDGET` в команде запуска сейчас не передаётся, поэтому по умолчанию 100000.
  Остаток прокси не сообщает — учёт свой (`harness/meter.py`).
- Проверяющая машина: 8 логических ядер (Xeon E5-2696 v4), 16 ГБ RAM, без GPU.
- Ключи API никогда не попадают в репозиторий. Ключ лежит в `.env`, он в `.gitignore`.
- Харнесс **не читает** поля `expected` и `feasible` из `task.json`: в финальном наборе их нет.
  Использовать их можно только в `scripts/evaluate.py`.
- `answer.txt` пишется **только рядом с `task.json`**, сразу после решения каждой задачи (`harness/writer.py`).
  Для невыполнимой задачи файл **не создаётся**.
- Решать без LLM можно и нужно, если шаблон распознан надёжно (`harness/fastpath/`): это 0 токенов.

## Карта репозитория

| Путь | Что там |
|---|---|
| `run_agent.py` | точка входа |
| `harness/config.py` | настройки из аргументов и `HARNESS_*`; значения по умолчанию = боевые |
| `harness/tasks.py` | загрузка `task.json` |
| `harness/runner.py` | быстрый путь для всех задач, затем агент: порядок (`plan`), 5 воркеров, сторож времени и бюджета, траектории |
| `harness/fastpath/` | детерминированные решатели по типам задач (`@register("<task_type>")`): `data_analysis.py`, `math_tasks.py`, `search.py`; умеют и ответить, и объявить задачу невыполнимой; тесты — `tests/` |
| `harness/solver.py` | решение задачи: сначала один вызов (`oneshot`/`coding`), иначе цикл агента — ReActAgent + bash → `ANSWER:`/`INFEASIBLE` → локальная проверка |
| `harness/oneshot.py` | один вызов вместо цикла агента: math/data_analysis — программа, которую запускает харнесс; search — ответ по базе в запросе; признаки невыполнимости без LLM; агент — запасной путь |
| `harness/coding.py` | coding за один вызов: модель присылает исправленные функции, харнесс подставляет их и гоняет тесты; противоречивые тесты → невыполнима без LLM |
| `harness/shell.py` | запуск shell-команд (таймаут, обрезка вывода, без секретов в env); без внешних зависимостей |
| `harness/estimator.py` | прогноз стоимости до запуска: маршрут (быстрый путь / coding / агент) + линейная модель; параметры — `harness/estimator_params.json` |
| `harness/answers.py` | итог решения (`Outcome`), приведение ответа к формату (`6668.0` → `6668`), признаки `INFEASIBLE`, условие без служебного хвоста |
| `harness/llm.py` | модели openJiuwen (`MeteredModel`): счётчик токенов, стоп по бюджету, лимит частоты, повторы при 429/5xx |
| `harness/meter.py` | стоимость = выходные + входные/10; общий бюджет, резерв на идущие вызовы (бюджет нельзя пересечь — прокси обрывает запуск), потолок на задачу |
| `harness/tools.py` | bash-инструмент агента поверх `harness/shell.py` |
| `harness/writer.py` | атомарная запись `answer.txt` и файла решений |
| `scripts/run_dev.py` | прогон на копии задач в Docker с флагами регламента + оценка |
| `scripts/evaluate.py` | баллы по `expected`/`check`, скрытые тесты coding, сводка по видам задач, токены по траекториям |
| `scripts/generate_tasks.py` | генератор задач 4 типов: шаблоны, перефразировки, невыполнимые; скрытые тесты coding в `hidden/` |
| `scripts/check_fastpath.py` | проверка быстрого пути на наборе с `expected` без LLM; ошибок должно быть 0 |
| `scripts/estimate.py` | прогноз стоимости для набора задач (таблица или JSON) |
| `scripts/fit_estimator.py` | подбор параметров оценщика по прогонам или по `trajectories/estimator_dataset.jsonl`, проверка на отложенных прогонах |
| `trajectories/` | собранные траектории (`raw/`) и обучающая выборка оценщика |
| `tasks_examples/` | 8 примеров от организаторов. **Не изменять** |
| `tasks_custom/` | наши невыполнимые примеры (`"feasible": false`): правильно — не создать `answer.txt` |
| `docs/` | регламент, ответы организаторов, план |

## Команды

```bash
python scripts/run_dev.py                      # полный прогон примеров в Docker (основная проверка)
python scripts/run_dev.py --only math_0004     # одна задача
python scripts/run_dev.py --no-build           # без пересборки образа
python scripts/run_dev.py --tasks tasks_custom # невыполнимые примеры: ни одного answer.txt
python -m unittest discover -s tests           # тесты решателей быстрого пути (без Docker и openJiuwen)
python scripts/generate_tasks.py --count 100 --seed 1 --force   # набор в tasks_generated/ (не коммитится)
python scripts/check_fastpath.py tasks_generated                # быстрый путь без LLM: ошибок должно быть 0
python scripts/run_dev.py --tasks tasks_generated               # репетиция финала: 100 задач в Docker
python scripts/estimate.py tasks_generated                      # прогноз стоимости без LLM
python scripts/fit_estimator.py --dataset trajectories/estimator_dataset.jsonl --write  # переподбор оценщика
python scripts/evaluate.py runs/<время>/tasks --original tasks_examples --logs runs/<время>/logs
```

Результаты прогона лежат в `runs/<время>/`: копия задач с ответами, `logs/trajectories_*.jsonl`.

## Как работать

- Перед изменением прочитай нужный раздел `docs/pipeline.md`, после — прогони `scripts/run_dev.py`.
  Изменение принимается, если баллы на примерах не упали, а расход токенов не вырос без причины.
  В описании PR пиши, сколько было и сколько стало.
- Стиль кода: Python 3.12, аннотации типов, `logging` вместо `print` (кроме итоговой сводки),
  комментарии и докстринги на русском, коротко. Без новых зависимостей без необходимости:
  каждая зависимость увеличивает образ и время сборки. Новую зависимость добавляй в `requirements.in`
  и пересобирай `requirements.txt` командой из его шапки.
- Одна задача не должна ронять весь прогон: исключения внутри решения ловятся и пишутся в траекторию.
- Новый решатель быстрого пути — с тестами в `tests/`: примеры организаторов, вариации формулировок и случаи,
  на которых решатель обязан вернуть `None` (незнакомое предложение, неполные данные). Неверный ответ отсюда
  никто не перепроверит, поэтому при любом сомнении — `None`. После изменения прогнать
  `scripts/check_fastpath.py` на сгенерированном наборе (лучше на нескольких сидах): ошибок должно быть 0.
- Новые формулировки задач добавлять в `scripts/generate_tasks.py` вместе с правильным ответом — так генератор
  проверяет и решатели, и агента. Новые виды невыполнимых задач — в `INFEASIBLE_KINDS`; прогнать их отдельно:
  `generate_tasks.py --infeasible-share 1.0 --infeasible-kinds <виды>`, затем `run_dev.py --tasks <набор>`.
- Правило «невыполнима без LLM» должно давать **0 ложных срабатываний** на выполнимых задачах всех размеченных
  наборов: ошибочно пропущенная выполнимая задача теряет баллы. Проверять так же, как сделано для
  `oneshot.missing_quantity` и `coding.contradictory_tests`.
- CI (`.github/workflows/ci.yml`) гоняет тесты, проверку быстрого пути, чистую сборку и запуск без сети на каждый
  push в `main`; результат — во вкладке Actions на GitHub.
- Изменение, которое меняет расход харнесса (промпты, маршруты, решатели), делает параметры оценщика устаревшими:
  прогнать сгенерированные наборы и переподобрать `harness/estimator_params.json` (`scripts/fit_estimator.py`),
  выгрузив новую выборку в `trajectories/`.
- Не трогать `tasks_examples/` и тесты внутри задач. Свои наборы задач — в отдельные папки.
- Ветка на каждую задачу, PR в `main`; `main` всегда собирается и проходит примеры.
