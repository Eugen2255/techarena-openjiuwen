### Проверено на ключе NeuralDeep (10.11)

- Id моделей точно совпадают с регламентом: `qwen3.8-27b`, `qwen3.8-27b-noreason`, `qwen3.6-35b-a3b`, `qwen3.6-35b-a3b-noreason`.
  В списке есть и другие модели (`qwen3.6-fp8`, `qwen3.8-flash-next-ru` и др.) — их использовать нельзя.
- `usage` приходит всегда. **Токены рассуждений уже входят в `completion_tokens`** (`qwen3.8-27b`: 62 = 56 рассуждений + 6 ответа),
  отдельно их прибавлять не нужно.
- Модели с рассуждениями дороже в десятки раз: на «17×23» `qwen3.6-35b-a3b` потратила 294 выходных токена, `-noreason` — 4.
- **Лимит одновременных запросов — 3 на аккаунт** (не 16, как в памятке), общий на все ключи аккаунта. При превышении — 429
  «Слишком много одновременных запросов». В харнессе: не больше 3 одновременных вызовов (`HARNESS_LLM_CONCURRENCY`).
- Какой код вернёт прокси организаторов после исчерпания 100K — неизвестно; харнесс останавливается после 5 неудачных задач подряд.
| Остаток бюджета от прокси | Нет | Свой учёт в `harness/meter.py`, жёсткие стопы перед каждым вызовом |
| Куда писать `answer.txt` | Рядом с `task.json` | `harness/writer.py` пишет только туда |
| Невыполнимая задача | Не создавать файл. Баллов за пропуск нет | Ответ `INFEASIBLE` или проваленные тесты → `answer.txt` не создаётся |
| Что такое «невыполнимая» | Нельзя точно решить при имеющихся данных | Гипотезы и примеры — `docs/pipeline.md`, раздел 5; `tasks_custom/` |
| Поля в финальном `task.json` | `expected` уберут, остальные останутся | Доступны `task_id`, `task_type`, `instruction`, `reward`, `check` |
| Типы задач | Только 4 типа из примеров, сложность и структура похожи | Шаблонные решатели оправданы |
| Тип задачи указан явно | Да | Маршрутизация по `task_type` |
| Вопросы search | Связаны со знаниями из базы данных (`kb/`) | Ответ ищем только в `kb/` |
| AgentForge-harness | Можно использовать | Не используем, пока не понадобится |
| Команда запуска контейнера | Опубликована, слово в слово как в регламенте | `scripts/run_dev.py` её повторяет. В ней **нет `-e BUDGET` и `-e OUT`**: без `BUDGET` харнесс берёт 100000, файл решений не нужен — считается только `answer.txt` |
| Модели для разработки | Только `qwen3.8-27b` и `qwen3.6-35b-a3b` (на всё время соревнования) | Остальное — их `-noreason` варианты на прогоне |

## Исходный текст

**Обзор вопросов после первой установочной встречи (07 ноября)**

- Использовать oJ обязательно? — Да.
- За пропуск нерешаемой задачи дают баллы? — Нет.
- Что подразумевается под понятием «Невыполнимая задача»? — Задача, которую нельзя точно решить при имеющихся данных.
- Откуда harness берёт размер бюджета токенов? — Ориентируйтесь на бюджет 100К токенов. При превышении лимита LLM перестаёт выдавать результаты. Бюджет будет передан модели в переменной окружения BUDGET — например, BUDGET=100000. Доступа к интернету нет, только API модели.
- Можно ли решать часть задач детерминированно без LLM? — Можно решить все, если получится.
- Вопросы будут связаны со знаниями из базы данных.
- Можно использовать AgentForge-harness? — Да.
- Когда будет опубликована команда для запуска контейнера? — 9 ноября.
- В примерах есть поле expected с ответом. В финальном наборе его уберут? Какие поля останутся доступны агенту? — В финальном наборе его уберут, остальные останутся.
- В финальном наборе для каждой задачи в task.json будет указано поле reward, как и в примерах? То есть агент сможет заранее видеть количество баллов за каждую задачу? — Да.
- Будут ли финальные задачи ограничены 4 типами из примеров и насколько их сложность и структура будут соответствовать тренировочному набору? — Будут ограничены, сложность и структура будут похожи.
- В каталоге каждой задачи нужно создать файл answer.txt. В этот файл надо записать ответ на задачу? — Да.
- Как оформить невыполнимую задачу: пустой ответ, отсутствие, файл? — Не создавайте файл.
- В задачах будет явно прописан тип задачи, как в примере? — Да.
- Куда точно сохранить answer.txt: рядом с task.json или внутри workspace? Для coding проверяются изменённые исходники? — Рядом.
- Будет ли агент получать информацию об оставшемся бюджете от прокси или должен самостоятельно учитывать расход? — Нет.

**Вопросы про оценку расхода токенов**

1. Метрики и точки оценки: до запуска, после каждого вызова, внутри генерации? MAE, относительная ошибка, штраф за недооценку — эти параметры будут выложены на сайт соревнования на следующей неделе.
2. Будут ли готовые трассы и размеченный обучающий набор? — Нет, не будет.
3. Какие будут доступны наблюдения: история сообщений, tool calls, usage, граф workflow, события сжатия? — Вы разрабатываете решение локально / с использованием предоставленного API, поэтому у вас будут любые наблюдения, которые вам интересны.
4. Среда: какие модели и версии openJiuwen, один агент или несколько, можно ли менять агента? — Для разработки можно использовать только qwen3.8-27b и qwen3.6-35b-a3b, доступ к ним будет на всё время соревнования. Версия openJiuwen берётся последняя с официального сайта. Агентов можно делать сколько угодно и каких угодно.
5. Допустимы ли опубликованный код, готовые веса и внешние данные? — Да, можно использовать любой код и модели, чья лицензия это позволяет; но запуск для оценки будет с фиксированной моделью.
6. «Сможем ли мы до запуска эффективно предсказать, сколько вычислений фактически потребуется для выполнения задачи агента?» — запуск это самый первый запуск или любая последующая итерация? — Для оценки будут даны новые запросы, их нужно будет предсказать до запуска.
