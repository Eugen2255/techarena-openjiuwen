# С чего начать

Гайд для команды и для ваших ИИ-ассистентов (Codex, Claude Code). Если в других файлах не сказано,
в каком порядке что делать, действуйте по этому файлу.

**Что мы делаем.** Docker-образ с агентом на openJiuwen. Агент за 1 час и общий бюджет токенов решает
как можно больше из 100 задач. Типы задач в примерах: `math`, `data_analysis`, `search`, `coding`.
15–25% задач невыполнимы. Баллы за задачи случайны. За неверный ответ штрафа нет, теряются только токены.
При равенстве баллов выигрывает тот, кто потратил меньше токенов.
Сдача — последний коммит в репозитории на момент закрытия (тариф NeuralDeep закрывается **20.11.2026 23:59:59 МСК**).

Читать по порядку: этот файл → `docs/regulations.md` (правила, 5 минут) → `docs/organizers_faq.md`
(ответы организаторов, они уточняют регламент) → `docs/pipeline.md` (план).

## Текущее состояние (10.11)

Каркас работает по ответам организаторов: образ собирается и запускается с флагами регламента (read-only,
`/tmp` в памяти, без привилегий); `answer.txt` — рядом с `task.json`; для невыполнимых задач файла нет;
бюджет из `BUDGET`; openJiuwen `0.1.20.post1`.

Замеры на NeuralDeep в боевой конфигурации (`qwen3.8-27b-noreason`, без `HARNESS_*`):

| Метрика | Значение |
|---|---|
| Примеры (`tasks_examples/`) | 8/8, 20/20 баллов, **1314 токенов** |
| Быстрый путь | 4 задачи за 0 токенов: `data_analysis` и `math` (`harness/fastpath/`, тесты в `tests/`) |
| Невыполнимые (`tasks_custom/`) | 4/4 распознаны, ни одного `answer.txt`, 1449 токенов (от 177 до 760 на задачу) |
| Образ | 1,39 ГБ (лимит 4 ГБ); сборка через зеркало — 6,5 минуты |

Что видно сразу:
- **Бюджет 100K, скорее всего, не узкое место:** задача агента стоит 170–410 токенов, 100 задач — порядка 20–25K.
  Важнее всего точность и распознавание невыполнимых; токены решают при равенстве баллов.
- **Основной расход — входные токены:** около 1000 на вызов (75% стоимости), хотя наш системный промпт ~100 токенов.
  Остальное добавляет openJiuwen: шаблон и описание инструмента. Это первая цель для экономии агента.
- **Невыполнимые задачи дороже выполнимых** (поиск несуществующего человека — 760). Бесплатные предпроверки
  (например, «имени нет в `kb/`») сэкономят больше всего.
- **Лимит NeuralDeep — 3 одновременных запроса на аккаунт** (в памятке написано 16). Харнесс держит не больше 3.
- **Время сборки:** через основной PyPI на медленном канале `pip install` шёл 56 минут, через зеркало — 5,5 минуты.
  У организаторов лимит 1000 с, так что чистую сборку надо замерить на быстрой сети без зеркала.

## 1. Подготовка (один раз, ~30 минут)

1. **Ключ NeuralDeep.** Код приглашения вида `НГУ-ХХХХ-ХХХХ` от координаторов активируйте на
   https://hub.neuraldeep.ru, затем скопируйте ключ в личном кабинете.
   - Один ключ одновременно можно использовать максимум с **2 IP-адресов**, иначе блокировка на 60 минут.
     Пользуйтесь своим ключом.
   - Лимиты: 60 запросов в минуту, 16 параллельных потоков на аккаунт.
   - Ключ никому не передавать и не коммитить.
2. **Поставить:** Git, Python 3.10+ (только стандартная библиотека — зависимости харнесса живут в образе),
   Docker Desktop (на Windows — с бэкендом WSL2). Проверка: `docker run --rm hello-world`.
3. **Склонировать репозиторий и создать `.env`:**
   ```bash
   git clone https://github.com/Eugen2255/techarena-openjiuwen.git
   cd techarena-openjiuwen
   cp .env.example .env        # Windows (PowerShell или cmd): copy .env.example .env
   ```
   Откройте `.env` в любом редакторе (на Windows: `notepad .env`) и впишите ключ после `LLM_API_KEY=`,
   без кавычек и пробелов:
   ```
   LLM_BASE_URL=https://api.neuraldeep.ru/v1
   LLM_API_KEY=sk-ваш-ключ
   ```
   - `.env` есть в `.gitignore` и не попадает в образ: `.dockerignore` пропускает только код харнесса.
     Ключ не коммитить и не пересылать в чаты.
   - Если сборка образа медленная, раскомментируйте в `.env` строку `DEV_PIP_INDEX_URL=...` (зеркало PyPI).
   - Скрипт `scripts/run_dev.py` сам читает `.env`; переменные, уже заданные в окружении, важнее значений из файла.
4. **Первый прогон**, чтобы убедиться, что всё работает. Первая сборка образа занимает 3–5 минут:
   ```bash
   python scripts/run_dev.py --only math_0004
   ```
   В конце должна быть строка `solved 1/1`. Потом можно прогнать все 8 примеров: `python scripts/run_dev.py`.

Если что-то не работает — раздел 6.

## 2. Как устроен код

Короткая карта — в `AGENTS.md`. Путь одной задачи:

`runner.plan()` выбирает порядок → `solver.gather_context()` собирает контекст **без LLM** →
`ReActAgent` openJiuwen с инструментом `bash` решает → `solver.extract_answer()` достаёт ответ →
`solver.local_check()` проверяет без LLM → `writer.save()` пишет `answer.txt`.
Токены считает `llm.MeteredModel` → `meter.TokenMeter`, итог по задаче пишется в `runs/<время>/logs/trajectories_*.jsonl`.

Скрипт `scripts/run_dev.py`:
1. копирует задачи в `runs/<время>/tasks`;
2. собирает образ `hack:dev`;
3. запускает его **с теми же флагами, что у организаторов** (read-only FS, `/tmp` в памяти, без привилегий);
4. в конце вызывает `scripts/evaluate.py`: какие задачи решены, баллы и токены.

## 3. Как работаем

- **Ветка на каждую задачу:** `git checkout -b <имя>/<что-делаю>`, затем PR в `main`.
  `main` всегда собирается и решает примеры.
- **Перед PR** обязательно прогнать `python scripts/run_dev.py` и написать в описании PR баллы и токены
  до и после изменения. Цель каждого изменения — меньше токенов при тех же баллах или больше баллов.
- **Нельзя** (это легко сделать случайно):
  - читать `expected` и `feasible` в харнессе (только в `scripts/evaluate.py`);
  - создавать `answer.txt` для невыполнимой задачи или класть его куда-то кроме папки рядом с `task.json`;
  - писать куда-то кроме `/tmp` и `/data/tasks`;
  - скачивать что-то при запуске;
  - вызывать локальные нейросети;
  - коммитить ключи;
  - менять `tasks_examples/`.
- **Новые зависимости** — только если без них никак: они увеличивают образ (лимит 4 ГБ) и время сборки
  (лимит 1000 с). Добавлять в `requirements.in` и пересобирать `requirements.txt` командой из его шапки.
- Не запускайте полные прогоны на одном ключе с трёх компьютеров одновременно (правило 2 IP).

## 4. Роли и первые задачи

Роли из `docs/pipeline.md`, раздел 8. Договоритесь, кто какую берёт.

**Инфраструктура и надёжность**
1. Репозиторий: https://github.com/Eugen2255/techarena-openjiuwen (приватный). Проверить, что у жюри
   (`promsoft`, `madrugado`) и у всей команды есть доступ (Settings → Collaborators).
   (Проверки на ключе NeuralDeep — id моделей, `usage`, учёт рассуждений, лимиты — уже сделаны, см. `docs/organizers_faq.md`.)
2. Замерить время чистой сборки (`docker build --no-cache`) на быстрой сети, например в GitHub Actions.
   Если она близка к 1000 с — сократить зависимости.
3. Отказоустойчивость: ответы 429 и 5xx от прокси, сторож времени. Уже проверено: без сети импорт и
   `tiktoken` работают, а при недоступном прокси прогон останавливается после 5 ошибок подряд.

**Агент и экономия токенов**
1. Прогнать все 8 примеров на всех 4 моделях (`HARNESS_MODEL=...` в `.env`).
   Собрать таблицу «модель × тип задачи → решено/токены».
2. Сократить расход: системный промпт, контекст в `gather_context`, число шагов (`HARNESS_MAX_STEPS`),
   выбор модели по типу (`solver.choose_model`), эскалация на модель с рассуждениями только при провале проверки.
3. Выяснить, сколько токенов съедают описания инструментов и служебные промпты openJiuwen.
4. Распознавание невыполнимых задач агентом: прогон на `tasks_custom/` должен дать
   `infeasible correctly skipped 4/4` при минимуме токенов.

**Данные и оценщик**
1. **Главный приоритет — детерминированные решатели** в `harness/fastpath/` для `search` и `coding`
   (готовы `data_analysis.py` и `math_tasks.py` — по ним видно устройство). Организаторы разрешили решать без LLM,
   а это 0 токенов и выигрыш при равенстве баллов. Решатель отвечает, только если шаблон распознан целиком;
   иначе возвращает `None`, и задачу решает агент. Тесты — как в `tests/test_fastpath_math.py`.
2. Генератор задач по 4 шаблонам с `expected` и `check` (формат как в `tasks_examples/`), с вариациями
   формулировок и невыполнимыми вариантами (`"feasible": false`, как в `tasks_custom/`). Цель — 300+ задач в `tasks_train/`.
3. Оценщик стоимости по траекториям. Организаторы будут проверять его отдельно: дадут новые запросы, расход надо
   предсказать до запуска (метрики опубликуют позже). Оценщик работает только по тексту задачи и её файлам.

## 6. Частые проблемы

| Симптом | Что делать |
|---|---|
| `Задайте LLM_BASE_URL и LLM_API_KEY` | Нет `.env` или в нём пустой ключ |
| `docker: command not found` или `Cannot connect to the Docker daemon` | Запустить Docker Desktop |
| Сборка образа идёт десятки минут | Медленный канал до pypi.org. Включить зеркало: `DEV_PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` в `.env` |
| Ошибка про `--cpus` | Docker Desktop выделено мало CPU: Settings → Resources |
| Все задачи с `error=...Connection error` | Неверный `LLM_BASE_URL` или ключ; проверить ключ на hub.neuraldeep.ru |
| 429 «Слишком много одновременных запросов» | Больше 3 одновременных запросов на аккаунт. Не запускайте параллельно несколько прогонов на одном аккаунте |
| 429 / ключ заморожен на 60 минут | Слишком частые запросы или больше 2 IP на ключ. Уменьшить `HARNESS_WORKERS` |
| `--local` на Windows не находит `bash` или `python3` | Запускать через Docker (по умолчанию) или из WSL |
| SSL `certificate has expired` при `--local` на Windows | В хранилище Windows устаревший промежуточный сертификат ISRG Root X2; в Docker проблемы нет |
